14  L12 — Multithreading in C/C++

Module 7 · Threads, Synchronization, Race Conditions

14.1 Why Multithreading?

Modern CPUs have multiple cores. A single-threaded program uses one — the rest idle. Threads exploit all cores.

  • Concurrency — tasks overlap in time (may time-share one core).
  • Parallelism — tasks run simultaneously on different physical cores.
  • Thread — lightweight execution unit sharing process memory.

14.2 std::thread — Creating and Managing Threads

#include <thread>

void work(int id) { /* ... */ }

int main() {
    std::thread t1(work, 1);   // starts immediately
    std::thread t2(work, 2);

    t1.join();   // main waits for t1
    t2.join();   // main waits for t2
}

⚠️ Always join() or detach() every std::thread.

Lambda thread:

int x = 10;
std::thread t([x]() { /* captures x by value */ });
t.join();

Pass by reference:

void increment(int &n) { n++; }
int count = 0;
std::thread t(increment, std::ref(count));
t.join();

14.3 Race Conditions and Data Races

int counter = 0;

void bad() {
    for (int i = 0; i < 1'000'000; i++)
        counter++;   // UNSAFE — load, add, store are three steps
}

Two threads can interleave these steps → both read the same value, both store the same incremented value → one update is lost. This is a data race → undefined behaviour.

14.4 std::mutex and std::lock_guard

#include <mutex>

int counter = 0;
std::mutex mtx;

void safe() {
    for (int i = 0; i < 1'000'000; i++) {
        std::lock_guard<std::mutex> g(mtx);   // locks here
        counter++;                              // critical section
    }                                           // unlocks when g is destroyed
}

std::lock_guard uses RAII — unlocks automatically even if an exception is thrown.

Deadlock: Thread A holds M1, waits for M2; Thread B holds M2, waits for M1 → both freeze.

Fix: always lock in the same order. Use std::scoped_lock(m1, m2) (C++17) for multiple mutexes.

14.5 std::atomic — Lightweight Synchronization

#include <atomic>

std::atomic<int> counter(0);

void safe() {
    for (int i = 0; i < 1'000'000; i++)
        counter++;   // hardware-guaranteed indivisible
}

Use std::atomic for a single shared variable. For compound operations across multiple variables, use a mutex.

14.6 Condition Variables — Producer–Consumer

#include <condition_variable>
#include <queue>

std::queue<int>         buffer;
std::mutex              mtx;
std::condition_variable cv;
const int               MAX = 5;

void producer() {
    for (int i = 0; i < 10; i++) {
        std::unique_lock<std::mutex> lk(mtx);
        cv.wait(lk, []{ return buffer.size() < MAX; });
        buffer.push(i);
        cv.notify_one();
    }
}

void consumer() {
    for (int i = 0; i < 10; i++) {
        std::unique_lock<std::mutex> lk(mtx);
        cv.wait(lk, []{ return !buffer.empty(); });
        int v = buffer.front(); buffer.pop();
        cv.notify_one();
    }
}

cv.wait(lock, predicate) releases the lock and sleeps. On wakeup, re-checks predicate — protects against spurious wakeups.

14.7 Thread Pools (Conceptual)

Pre-create N worker threads. Tasks go into a queue; idle threads pick them up. Avoids thread-creation overhead for many short tasks.

14.8 Testing Multithreaded Code

  • Stress test — high iteration counts make races more likely to surface.
  • ThreadSanitizer — build with -fsanitize=thread -g; detects data races at runtime.
  • Code review — every shared variable should be atomic or mutex-protected.

14.10 Worked Example — Parallel Array Sum

#include <thread>
#include <vector>
#include <iostream>

void partial_sum(const std::vector<int> &v, int lo, int hi, long long &res) {
    res = 0;
    for (int i = lo; i < hi; i++) res += v[i];
}

int main() {
    std::vector<int> v(1'000'000, 1);
    long long s1 = 0, s2 = 0;
    int mid = v.size() / 2;

    std::thread t1(partial_sum, std::cref(v), 0, mid, std::ref(s1));
    std::thread t2(partial_sum, std::cref(v), mid, (int)v.size(), std::ref(s2));

    t1.join(); t2.join();
    std::cout << "Sum: " << (s1 + s2) << "\n";   // 1,000,000
}

s1 and s2 are distinct — no sharing, no mutex needed.
